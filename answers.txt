Q1: Why might we consider using Git?
Answer: Git is a version control system for our source means it keeps track of all changes that we as developers made to it. By keeping this history , Git insures that we can undo any of our actions that lead to unwanted results. Additionally, Git helps team projects and sources to don’t override. For instance if more than one person is working on a file each of their changes may cause issues for the code . By having Git we are able to merge all team mates work in one file without encountering override in file.also since Git holds all the history and data of files in the cloud if you ever lost your access to your local machine you can always get your files back from the cloud.

Q3: What is difference between Merging and Rebasing?
Answer: Merging means when we create races on our main repo and change existing file we mxi all those changes into one and update the file to the final version. It’s safe and don’t destruct the existing file. However when we use Rebase , we update the whole changes we made from beginning till now. by doing this it ensure that changes happen throughout the process are linear and make history of your commits more simple for you and your team. Since rebase put all branches into one it may cause issues for other members who are working on different branch and if you rebase push rebase to public repo you may cause situation where git for other members get confused and fully mess the history and version control of your project. Because of this rebase is safe to used on local repos and Merge used on public ones so these forms of issues won’t happen.
